🎮 What Is repos-and-dungeons?

Most people who work with code have the same problem: a project grows into hundreds of folders, and it becomes hard to keep a mental picture of what lives where. repos-and-dungeons solves that by drawing your project as a dungeon map instead of a list of files.

The idea is simple and a little playful. A folder is a room. A subfolder is a room further inside the dungeon. A file you have never looked at is covered in fog, so you can see at a glance how much of the dungeon is still unexplored. A test that is currently failing appears as a monster blocking the way. When the test passes again, the monster is defeated and the room is clear.

On top of that map, an AI assistant moves around like a character in a game. As it opens files and reads code, the fog lifts around it. You are not reading a log file or a wall of output — you are watching a small hero light up the dark corners of your own project, one room at a time.

✨ What You Will See on Screen

  • Rooms that match your folders. The layout of the dungeon mirrors the layout of your project, so the map is genuinely useful and not just decorative.
  • Fog over unread code. Areas the assistant has not explored yet stay hidden, giving you an instant sense of how much ground is left to cover.
  • Monsters for failing tests. A red test becomes a creature standing in a room. Fix the test, and the creature disappears from the map.
  • A moving adventurer. You can follow the assistant's path through the dungeon as it reads and searches your files.
  • Smooth pixel-art rendering. The map is drawn with a real-time graphics engine, so it scrolls and animates smoothly even on large projects.
  • A legend and mini-map. Colours, symbols, and a small overview help you stay oriented when the dungeon gets big.

None of this changes your code. The dungeon is a view layered on top of your project, like a window you can leave open on a second screen while you work.

🗺️ How to Read the Dungeon

The map is designed to be understood in a few seconds, even if you have never played a dungeon game before.

  • A room is a folder. Big rooms are heavily populated folders. Small rooms are folders with only a file or two.
  • Dark areas are unexplored files. If a corridor is still foggy, that part of your project has not been read yet.
  • A monster means something is broken. Monsters sit where a failing test lives. The scarier the creature, the more attention that area needs.
  • A cleared room is healthy. Bright, empty rooms mean the code there has been reviewed and the tests are passing.
  • The adventurer is the assistant. Where the character stands is where the AI is currently working.

After a few minutes with the map open, most people find they can describe the shape of their project from memory — something a file tree rarely achieves.

🧭 A Typical First Session

Here is what a relaxed first run usually looks like. You start by opening the application on Windows and selecting the folder you want to explore. The dungeon appears almost immediately, mostly covered in fog, with a single small room lit up where the assistant begins.

As the assistant moves, corridors open, side rooms appear, and the map fills in. If a test is failing somewhere deep in the project, a monster shows up in that room and stays there until the test is fixed. Within a few minutes you have a picture of your project that is far easier to remember than a folder listing.

When you are finished, simply close the window. Nothing is left running in the background, and your project files are untouched.

🛡️ Troubleshooting

  • The download did not start. Return to the releases page and click the download link again. Some browsers ask for confirmation before saving a file.
  • You cannot find the downloaded file. Open File Explorer and check the Downloads folder. Windows usually puts downloaded items there by default.
  • Windows shows a security prompt. This is a standard message for software downloaded from the internet. Choose the option to keep and open the file, since it comes from the official project page.
  • The window opens but the map stays empty. Close the application, reopen it, and select your project folder again. Very large projects can take a moment to draw the first time.
  • The page will not load. Check your internet connection and try again. The download page lives on GitHub, which is occasionally slow during busy periods.

If a problem persists, the project's issue tracker is the best place to describe what happened, including what you saw on screen.

❓ Frequently Asked Questions

Is repos-and-dungeons free?

Yes. It is open source and free to download and use.

Do I need to know how to code?

No. If you can download a file and open a program, you can run it. The dungeon is meant to be readable by anyone.

Does it send my code anywhere?

No. Everything runs locally on your own computer. Your project stays where it is.

Will it change my files?

No. The application only reads your project to draw the map. It is a view, not an editor.

Which kinds of projects work best?

Any project with folders and files. Projects that include automated tests get the most out of the monster feature, because failing tests appear directly on the map.

Can I use it on more than one project?

Yes. You can point it at any project folder you like, one at a time, and each one gets its own dungeon.
